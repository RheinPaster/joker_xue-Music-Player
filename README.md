# 薛之谦音乐播放器 · 带逐字歌词对齐

一个薛之谦主题的 Electron 桌面音乐播放器，**个人自用为主**。
除了常规播放功能，它解决了一个具体问题：
**把只有「整行时间轴」的 LRC 歌词，升级为「每个字都有时间戳」的增强型 LRC**，
从而实现类似 QQ 音乐的逐字点亮效果。

> 本仓库**只包含代码**：不含音频文件，不含封面图片，不含完整歌词。
> 使用者需自行准备拥有合法授权的素材，详见文末「版权与素材说明」。

## 功能

**播放**
- 播放/暂停、上一首/下一首、进度拖拽、音量、顺序/单曲循环/随机
- 本地文件夹扫描：任何放进 `music/` 的音频都会被识别
- 未收录进曲目库的文件自动归入「本地音乐」，一样可播
- 键盘操作：空格播放/暂停，左右方向键切歌

**歌词**
- 侧栏大段滚动预览 / 封面沉浸模式（模糊封面作背景 + 单行大字），一键切换
- **逐字填充**：当前行从左到右连续"刷"亮，字内平滑扫过而非整字跳变
- 自动获取：从公开歌词库 [LRCLIB](https://lrclib.net) 按歌名+歌手+时长严格校验后抓取
- 时间轴微调：`− 歌词同步 ＋` 每档 0.5 秒，**按歌曲分别保存**
- **手动逐字打轴**：边听边按空格给每个字打时间，输出与自动对齐**同一种格式**

**其他**
- 封面自动获取（iTunes Search API，1400×1400）
- 收藏 / 搜索 / 播放历史，状态自动持久化
- 频谱可视化、响应式布局
- 内置**原创合成旋律**引擎：没有音频文件时也有声音，不至于一片死寂

## 运行

```bash
npm install
npm start
```

Windows 下也可以直接双击 `start.bat`——它会自动切到脚本所在目录，
检测到缺 Electron 时自动走国内镜像安装，然后启动。

> 首次运行会自动创建 `music/`、`covers/`、`lyrics/` 三个目录并写入使用说明。
> 若 Electron 下载慢：`$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"` 后再 `npm install`。

## 技术要点

### 用本地 HTTP 服务器做中转，而不是让页面直接读文件

```
Electron 主进程 (main.js)
   ├── 起 http://127.0.0.1:37914 本地服务器
   │     ├── /                    → renderer/ 作为静态站点
   │     ├── /media?dir=&name=    → 流式返回音频/图片/歌词（支持 Range）
   │     └── /api/music|list|covers|lyrics → 目录清单 JSON
   └── 开 BrowserWindow 加载该地址
         └── 页面只能通过 window.JX.* 与主进程通信（8 个方法）
```

三个理由：

1. **音频 seek 需要 HTTP Range**（`206 Partial Content`），`file://` 加载在拖进度条时兼容性问题多；
2. **渲染进程不该有文件系统权限**——窗口为 `contextIsolation: true` + `nodeIntegration: false`，页面拿不到 `require` / `fs`；
3. **目录白名单防路径穿越**——`/media` 校验请求目录在白名单内，且解析后的绝对路径**父目录**也在白名单内。

### 逐字填充的实现

每行渲染两层文字（底层暗色、上层亮色），上层每个字用 `clip-path: inset(0 X% 0 0)` 裁剪，
由 `requestAnimationFrame` 逐帧推进裁剪宽度（`<audio>` 的 `timeupdate` 只有约 5fps，做逐字填充会一顿一顿）。

- `.lrc` 是**增强型**（带 `<mm:ss.xx>` 逐字标签）→ 用相邻两字的真实时间插值出字内进度；
- 普通 `.lrc` 只有整行时间 → 按行内进度线性插值，仍然平滑，但无法反映长音/快字。

**只有标记为「手动打轴」的歌词才启用逐字填充。** 自动对齐的逐字时间精度有限，
强行逐字点亮会看起来乱跳，反而不如整句高亮干净——这是刻意的降级策略。

### 歌词匹配的严格校验

`lib/lyrics-match.js` 是纯函数模块，**主进程与诊断脚本共用同一份**，保证"测过的就是跑着的"：

- 歌名必须匹配（归一化后精确或互相包含）；
- 歌手必须匹配，且支持**别名表**（例如同一歌手的英文名与繁体名视为同一人）；
- 时长只用于**排除明显不是同一版本的**候选和排序（容差 10% 或 20 秒）——
  歌名+歌手已能锁定歌曲，Live / 重制版本时长有出入仍应给出歌词；
- 有音频文件时用**真实时长**参与校验，不用估算值。

## 逐字对齐工具链（本项目的核心）

公开歌词库只提供**整行**时间轴，行内每个字什么时候亮只能靠平均分配猜，长音和快字必然对不上。
本项目的做法是自己算出来：

```
① Demucs 分离人声（去掉伴奏干扰）
② faster-whisper (large-v3) 识别 → 得到每个词/字的粗略时间
③ 用「已知歌词文字」与识别结果做字符序列对齐（difflib.SequenceMatcher）
   匹配上的字用真实时间；识别错的字在前后锚点之间线性插值（优雅降级）
④ 输出增强型 LRC：[00:12.34]<00:12.34>字<00:12.90>字…
```

### 用法

```bash
# 首次：下载模型（约 2.9GB，走 hf-mirror.com 镜像，支持断点续传）
python tools/download-model.py large-v3

# 对齐一首（默认不覆盖原 LRC，输出 <原名>.aligned.lrc + .report.json）
python tools/align-lyrics.py --audio "music/song.mp3" --lrc "music/song.lrc"

# 确认满意后覆盖原文件（原文件先备份为 .bak，可随时还原）
python tools/align-lyrics.py --audio "music/song.mp3" --lrc "music/song.lrc" --replace
```

常用参数：`--no-vocals`（跳过人声分离，快一倍）、`--model medium`（小模型）、`--device cpu`（无 N 卡时）。

### 关键设计决策：人声分离不是"越用越好"

这是实测出来的结论，不是照抄常规做法。对 42 首歌各跑两种配方做对照（`tools/best-align.py`，耗时 95.8 分钟）：

| 配方 | 平均匹配率 | 更优首数 | **完全锚定不上的** |
| --- | --- | --- | --- |
| A：带 Demucs 人声分离 | 0.520 | 16 首 | **9 首** |
| B：跳过人声分离 | **0.581** | **22 首** | — |

- 有一批老录音**带分离后一行都锚定不上（匹配率 0）**，跳过分离反而能到 0.77~0.79；
- 也有少数歌（如《环》0 → 0.72）**只有带分离才救得回来**；
- **不存在万能配方**——所以 `best-align.py` 的做法是逐首跑两遍、保留匹配率更高的那个
  （提升不到 2% 就不折腾），`redo-low.py` 则内置了那批老录音的清单。

实验原始数据归档在 `_lab/`，详见 `_lab/README.md`。

### 自检工具

```bash
python scripts/test-align.py                       # 对齐算法单元测试（合成数据，秒级，无需 torch）
python scripts/verify-aligned.py "music/song.lrc"  # 检查结果：标签数 / 时间倒流 / 节奏离散度
node   scripts/diagnose-lyrics-sync.js "music"     # 用播放器的匹配规则逐首检查能否命中歌词
```

### 实测数据（本机 RTX 5080 Laptop）

| 指标 | 曲目 A | 曲目 B |
|---|---|---|
| 逐字标签 | 447 | 468 |
| 时间戳倒流（应为 0） | 0 | 0 |
| 行内节奏离散度 CV（平均分配为 ≈0） | 0.44 | 0.29 |
| 字间距 中位 / 最长 | 0.30s / 3.22s | 0.32s / 1.80s |
| 与「平均分配」的平均偏差 | 1.01s（最大 25s） | 0.48s |
| 单曲耗时 | 约 55s | 约 26s |

> 「时间戳倒流」是必须为 0 的指标——对齐结果里出现时间倒退，播放器就会跳字。
> 字符匹配率因曲目而异（实测 64%~88%）；匹配率过低的行自动退回插值兜底，**不会比原来更差**。
> 模型与对齐**全程本地离线**运行。

## 项目结构

```
main.js                 Electron 主进程（HTTP 服务 + 媒体流 + IPC + 外部 API 代理）
preload.js              contextBridge 桥接（8 个方法）
lib/
  lyrics-match.js       歌词候选匹配规则（纯函数，主进程与诊断脚本共用）
  mp3-duration.js       不依赖库直接解析 MP3 头算时长
renderer/
  index.html            界面骨架
  css/style.css         主题样式与响应式
  js/app.js             主逻辑（播放/队列/歌词同步/搜索/收藏/手动打轴）
  js/audio.js           双音频引擎（真实文件 + WebAudio 合成演示）+ 频谱分析
  js/ui.js              DOM 渲染、原创矢量 SVG、逐字填充算法
  js/store.js           状态持久化
  data/songs.js         曲目元数据（id / 标题 / 专辑 / 年份 / 时长 / 调色板）
tools/                  Python 工具链：逐字对齐、批量、配方择优、诊断、模型下载
scripts/                Node/Python 维护脚本：数据自检、歌词抓取、测试与验证
_lab/                   对齐实验的过程证据（含对照数据与说明）
```

各模块职责与关键取舍的完整说明见 **[DESIGN.md](DESIGN.md)**。
