## 二、核心实验：42 首歌 × 两种配方对照

这是 `best-align.py` 跑出来的完整对照数据（耗时 **95.8 分钟**）。

### 汇总

| 配方 | 平均匹配率 | 更好的首数 | 完全为 0 的首数 |
| --- | --- | --- | --- |
| A：带 Demucs 人声分离 | 0.520 | 16 首 | **9 首** |
| B：跳过人声分离 | **0.581** | **22 首** | — |

### 关键发现：Demucs 不是"越用越好"

**不分离反而明显更好的（差距 ≥ 0.15）——6 首：**

| 歌曲 | 带分离 | 不分离 | 差距 |
| --- | --- | --- | --- |
| 动物世界 | **0** | 0.787 | 0.787 |
| 慢半拍 | **0** | 0.780 | 0.780 |
| 怪咖 | **0** | 0.773 | 0.773 |
| 黄色枫叶 | **0** | 0.770 | 0.770 |
| 像风一样 | **0** | 0.630 | 0.630 |
| 爱情宣判 | 0.286 | 0.753 | 0.467 |

**带分离反而明显更好的（差距 ≥ 0.15）——5 首：**

| 歌曲 | 不分离 | 带分离 | 差距 |
| --- | --- | --- | --- |
| 环 | **0** | 0.720 | 0.720 |
| 被人 | **0** | 0.592 | 0.592 |
| 刚刚好 | **0** | 0.300 | 0.300 |
| 潘金莲 | 0.583 | 0.791 | 0.208 |
| 念 | 0.623 | 0.803 | 0.180 |

### 结论

1. **两种配方各有一批"完全为 0"的歌**——不是效果差，是**一行都锚定不上**。
   这说明分离与否会决定成败，而不是微调精度。
2. **不存在万能配方**：带分离赢 16 首，不分离赢 22 首。
3. 所以 `best-align.py` 的做法是**逐首跑两遍、保留匹配率高的那个**
   （代码里 `if cur is not None and best[0] <= cur + 0.02` 就是"提升不到 2% 就不折腾"的阈值）。
4. 老录音（《动物世界》《慢半拍》《怪咖》《黄色枫叶》这批早期作品）
   分离后反而全废——**猜测是分离残留干扰了识别**，所以 `redo-low.py`
   对这批歌内置了"跳过分离"重跑的清单。

## 三、这套实验怎么讲（面试话术）

> 「我一开始按常规做法加了 Demucs 人声分离，以为分离越干净识别越准。
> 结果跑批量的时候发现有 9 首歌**一行都锚定不上**，匹配率全是 0。
> 我拿 42 首跑了完整对照，发现带分离的 16 首更好、不分离的 22 首更好，
> 而且两边各有一批成绩为 0——说明这不是精度微调，是配方选择问题。
> 后来就改成逐首跑两种配方取优，耗时翻倍但把平均匹配率从 0.52 提到 0.58，
> 更重要的是把 9 首零命中的救回来了。」

**这段值得背下来。** 它包含四件面试官想听的事：
发现异常 → 设计对照 → 量化结论 → 改方案并验证改善。

## 四、复现方式

```bash
# 单曲打样
python tools/align-lyrics.py --audio "music/怪咖.mp3" --lrc "lyrics/怪咖.lrc" --no-vocals

# 完整对照（会重新往这里写 *_vocal / *_novocal）
python tools/best-align.py --threshold 0.8

# 重跑低匹配率的歌（内置清单，走"跳过分离"）
python tools/redo-low.py
```

> **注意**：复现需要 whisper 模型（`models/` 里已有，4.4GB）和 NVIDIA GPU。
> 本机是 RTX 5080 Laptop，单曲耗时约 26~80 秒。
