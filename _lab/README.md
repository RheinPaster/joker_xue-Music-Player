# `_lab/` —— 逐字对齐实验记录

这个目录保存「歌词逐字对齐」流水线在调参阶段留下的可复现记录。

它存在的理由很直接：`tools/best-align.py` 的核心设计（逐首跑两种配方取优）不是猜的，
而是基于这里记录的对照数据得出的。没有这些数据，「为什么不能只用 Demucs」
这个问题就只能凭印象回答。

## 一、单曲打样（3 首）

方案可行性验证，命令为 `align-lyrics.py --no-vocals`：

| 曲目 | 匹配率 | 锚定行数 | 字符数 |
| --- | --- | --- | --- |
| 其实 | **0.947** | 31 / 33 | 286 |
| 木偶人 | **0.830** | 32 / 32 | 436 |
| 怪咖 | **0.773** | 31 / 31 | 311 |

匹配率 0.77~0.95 表明大部分字能够依据识别结果锚定真实时间，
而不是全靠平均分配推测——方案成立，才值得进入批量处理。

## 二、核心实验：42 首 × 两种配方对照

由 `best-align.py` 跑出，总耗时 **95.8 分钟**。

### 汇总

| 配方 | 平均匹配率 | 更优首数 | **完全锚定不上的** |
| --- | --- | --- | --- |
| A：带 Demucs 人声分离 | 0.520 | 16 首 | **9 首** |
| B：跳过人声分离 | **0.581** | **22 首** | — |

### 关键发现：Demucs 并非「越用越好」

**跳过分离明显更优的（差距 ≥ 0.15）——6 首：**

| 曲目 | 带分离 | 不分离 | 差距 |
| --- | --- | --- | --- |
| 动物世界 | **0** | 0.787 | 0.787 |
| 慢半拍 | **0** | 0.780 | 0.780 |
| 怪咖 | **0** | 0.773 | 0.773 |
| 黄色枫叶 | **0** | 0.770 | 0.770 |
| 像风一样 | **0** | 0.630 | 0.630 |
| 爱情宣判 | 0.286 | 0.753 | 0.467 |

**带分离明显更优的（差距 ≥ 0.15）——5 首：**

| 曲目 | 不分离 | 带分离 | 差距 |
| --- | --- | --- | --- |
| 环 | **0** | 0.720 | 0.720 |
| 被人 | **0** | 0.592 | 0.592 |
| 刚刚好 | **0** | 0.300 | 0.300 |
| 潘金莲 | 0.583 | 0.791 | 0.208 |
| 念 | 0.623 | 0.803 | 0.180 |

### 结论

1. **两种配方各有一批匹配率为 0 的曲目**——不是效果差，而是**一行都锚定不上**。
   这说明是否分离决定的是成败，而不是精度微调。
2. **不存在万能配方**：带分离在 16 首上更优，不分离在 22 首上更优。
3. 因此 `best-align.py` 采用**逐首跑两遍、保留匹配率更高者**的策略
   （代码中的 `if cur is not None and best[0] <= cur + 0.02` 即「提升不到 2% 就不覆盖」的阈值）。
4. 一批老录音（《动物世界》《慢半拍》《怪咖》《黄色枫叶》）在分离后全部失效，
   推测是分离残留干扰了识别——因此 `redo-low.py` 为这批曲目内置了
   「跳过分离」的重跑清单；`redo-low.py` 的重跑记录显示，
   这批曲目跳过分离后匹配率可达 0.77~0.99。

## 三、实验记录的复现方式

```bash
# 单曲打样
python tools/align-lyrics.py --audio "music/怪咖.mp3" --lrc "lyrics/怪咖.lrc" --no-vocals

# 完整对照（会重新向本目录写入 *_vocal / *_novocal）
python tools/best-align.py --threshold 0.8

# 低匹配率曲目重跑（内置清单，走「跳过分离」）
python tools/redo-low.py
```

> 复现需要 faster-whisper 模型（`models/` 中已有）与 NVIDIA GPU。
> 参考数据在一台 RTX 5080 Laptop 上产生，单曲耗时约 26~80 秒。
